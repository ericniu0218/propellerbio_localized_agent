01PLATFORM & DEPLOYMENT

Off mock mode, onto real infrastructure

Owns: GPU serving, the real database, CI, and the deployment guide.

What's built

Mock mode (fake model replies, SQLite). config/models.yaml already names the three target models. app/models/http_client.py exists but has never been run against a real server. docker-compose.yml has a real profile. docs/HARDWARE.md has a GPU memory budget.

What's missing, and how

  1. GPU server + real models. Confirm hardware against the budget in docs/HARDWARE.md. Download the weights named in config/models.yaml onto that machine — no internet access afterward, that's the air-gap rule. Serve each with vLLM or SGLang using the real Compose profile as a starting point; you'll need to fix the volume paths and --model args to match where weights actually land.
  2. Verify HTTPModelClient against a live server. Start one vLLM instance, point DIRECTOR_LLM_URL at it, set AGENT_PACK_MODE=real, send one message through the full API. Likely breakage: streaming-format differences between vLLM versions, and whether chat_template_kwargs is really how your version wants thinking-mode toggled — that's a guess in the code today.
  3. Real Postgres + migrations. Point DATABASE_URL at real Postgres. Add Alembic, generate a migration matching app/db/models.py. From here on, schema changes go through migrations, not the current auto-create.
  4. CI. A GitHub Actions workflow in both repos: install deps, run pytest. Nothing runs tests today except a human typing the command.
  5. docs/DEPLOYMENT.md. Written for an IT person who has never seen this project — Compose, env vars (.env.example is the checklist), the air-gap check, Postgres.
Done when AGENT_PACK_MODE=real answers a real question with a real model, end to end. CI is green on a PR. A new IT person follows docs/DEPLOYMENT.md without asking you anything.

02IDENTITY & ACCESS

Real login, real permissions, a real review

Owns: SSO, RBAC/workspaces, and the security pass.

What's built

A trivial user_id string, trusted with no verification anywhere. A toy app/compliance/rbac.py::StaticPermissionSource (in-memory, connected to nothing real). Already decided with the client: departments and reviewers are admin-managed in-app, not pulled from Keycloak.

What's missing, and how

  1. Keycloak. Stand it up (official Docker image), create a realm and an OIDC client. Decide with IT how company accounts get in — directory sync, or manual.
  2. JWT verification. New app/auth/: a verify_token() function checking signature/expiry/audience against Keycloak's JWKS endpoint, plus a get_current_user() FastAPI dependency on every route. This changes the contract — coordinate with Workstream 6 before shipping it.
  3. Department/reviewer admin. New app/org/: a Department model, endpoints to assign a user to one and set its reviewer(s) — per the decision in docs/WORKFLOW.md §1. Workstream 5's review flow depends on this.
  4. Real workspaces + RBAC. New app/workspaces/: Workspace (personal/team/company) and WorkspaceMembership. Update app/tools/rag_search.py to filter by real membership via a SQL join — its own docstring already names this as the intended extension point.
  5. Security review. Sandbox escape vectors (app/tools/sandbox.py), injection surface outside the ORM, whether the audit log is genuinely append-only under real Postgres grants (docs/ARCHITECTURE.md §8 states the intent; nothing enforces it on SQLite today).
Done when Logging in requires a real company account. A user genuinely cannot pull up another team's documents through any path, including via an agent — test this adversarially, don't just check that the UI hides it.

03KNOWLEDGE BASE & INGESTION

From three sample files to the company's real library

Owns: the vector store, real document ingestion, and file uploads.

What's built

app/tools/rag_search.py and literature_search.py are real tool interfaces — backed by a KeywordOverlapIndex reading 3 sample text files. No vector DB, no embeddings, no real pipeline. No file upload capability anywhere yet.

What's missing, and how

  1. A real vector store. pgvector is the documented default (docs/ARCHITECTURE.md §9) — add the extension to Postgres, create a real content_chunks table (shape sketched in docs/WORKFLOW.md §8). Qdrant is the documented alternative if the team prefers a dedicated service.
  2. A self-hosted embedding model. Must run locally — no external API calls anywhere in this system. An open-weight embedding model served alongside the LLMs, or via sentence-transformers on CPU/GPU, works.
  3. Swap the search backend. Replace KeywordOverlapIndex with a real similarity query — both tool files already define a VectorIndex protocol specifically so this swap doesn't touch calling code.
  4. Document ingestion. A script that walks the company's real SOPs/study reports/protocols (ask where they actually live — don't assume), chunks, embeds, and stores them with doc_id/section preserved for citations.
  5. File uploads. New app/uploads/ per docs/WORKFLOW.md §5: accept a file, extract text (pypdf, python-docx, openpyxl/pandas, python-pptx — instrument CSVs already parse via app/tools/lab_connectors.py), chunk into the same index, and have the Runner produce a summary card. Build app/schemas/brief.py now if it doesn't exist — shape is in docs/UX.md §5.
Done when Asking about a real company topic returns real company documents with correct, clickable citations. Dragging in an actual SOP PDF produces a sensible summary card in a reasonable time.

04AGENT INTELLIGENCE & COMPLIANCE

Make the Director actually plan

Owns: dynamic planning, sandbox hardening, compliance readiness.

What's built

A working reject/retry/escalate loop — but the Director's plan is always the same hardcoded two-step shape (research → synthesis), see app/agents/director.py::plan. The sandbox (app/tools/sandbox.py) is a subprocess with basic resource limits, explicitly documented as not network-isolated. The audit log is designed with 21 CFR Part 11 in mind but never reviewed by a compliance professional.

What's missing, and how

  1. Real dynamic planning. Replace the hardcoded two-node template with a model call asking the Director for a JSON task graph (nodes, dependencies, assigned_to, domain, complexity). Real models don't always produce valid JSON on the first try — add parse-and-retry, and fall back to today's two-node template if it still fails. Keep that fallback; don't remove the safety net.
  2. Sandbox hardening. Replace the subprocess with real isolation — a locked-down Docker container per execution (--network=none, cgroup limits, a throwaway tmp mount) is the minimum; gVisor or Firecracker for more. Depends on Workstream 1 for where this actually runs.
  3. Prompt tuning against real models. Only possible once Workstream 1 has a live model. The JSON-producing prompts (Runner.classify, extract_entities, the new planning prompt) were only validated against a deterministic mock — expect real models to need tighter instructions or few-shot examples.
  4. Compliance-readiness document. Not a sign-off — a clear mapping from each relevant 21 CFR Part 11 requirement to how app/compliance/audit.py and AuditLogRow address it, so an actual reviewer has something concrete instead of reverse-engineering the code.
Done when Two genuinely different requests produce two genuinely different task graphs. The sandbox can't reach the network or escape its filesystem — try to break it. A compliance reviewer can read one document and know what to check.

Sharing, reviews, recipes — the whole product layer

What's built

Nothing yet — this workstream is docs/WORKFLOW.md turned into code. Its event types (share.created, review.requested, review.decided, item.updated, recipe.started, recipe.completed, notification.created) are documented but not yet added to app/schemas/enums.py::EventType.

06FRONTEND & UX POLISH

Both clients, accessibility, and the copy guide

Owns: the terminal client, the web client, and how the system speaks.

What's built

Both clients work end to end against mock mode: sessions, live agent status, approvals, a tier picker and "Create Agent" shortcut (web client), a right-hand running-agents panel. Neither streams token-by-token into the final answer. Neither reconnects if the connection drops. No trust badges, no technical-details toggle, no accessibility pass, no copy guide, no admin dashboard.

What's missing, and how

  1. Token streaming. The backend already emits agent.token events with live text — both clients wait for task.completed instead (see agentpack_app.py's docstring: a request can involve multiple agents drafting in sequence, so naive streaming looks like the answer rewriting itself). Fix: stream only the last agent's tokens, using the task.planned event's node list to know when you're on the final step.
  2. Reconnection. Wrap the SSE consumption in both clients in a retry-with-backoff loop; on reconnect, re-fetch /sessions/{id}/agents and /history to recover state.
  3. Trust badges + technical-details toggle. Add friendly_label/ trust_status to AgentCard/AgentStatusPayload (additive — coordinate with anyone else mid-edit on those schemas), compute trust_status from whether Director review happened, render a badge in both clients.
  4. Accessibility pass. A real keyboard-only and screen-reader pass on app/static/index.html. Fix tab order, add ARIA labels on the custom dropdown and approval buttons, check the earthy palette's contrast against WCAG AA — verify, don't assume the muted tones pass.
  5. docs/COPY_GUIDE.md. A table mapping every internal technical term to the plain word shown in the UI, plus tone rules. Most of the mapping already exists in bedrock-private-ai's agentpack/friendly.py — explain the reasoning, don't just restate the code.
  6. Admin dashboard. New app/metrics/ — counters only (tasks completed, docs condensed, recipes run, estimated minutes saved), admin-only endpoints, a page showing adoption/most-used-recipes/review-queue-size. No content tracking, per the client's requirement.
Done when The chat feels responsive even before real models exist. A dropped connection recovers on its own. A screen-reader-only user can complete the 5-minute usability checklist in docs/UX.md §9.
